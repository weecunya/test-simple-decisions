Deribit Crypto Tracker API

Асинхронное REST API приложение для периодического сбора и предоставления данных по индексу цен криптовалют (BTC, ETH) с биржи Deribit.
Проект реализован с акцентом на чистую архитектуру, масштабируемость и широкое покрытие тестами.

 Стек технологий
 * Backend: Python 3.11+, FastAPI, Pydantic
 * Database: PostgreSQL, SQLAlchemy 2.0 (async), asyncpg
 * Background Tasks: Celery, Redis (Broker), aiohttp
 * Testing: pytest, pytest-asyncio, aiosqlite, httpx
 * Infrastructure: Docker, Docker Compose, Github Actions

 Design Decisions (Архитектурные решения)
В ходе разработки были приняты следующие инженерные решения:
 * Слоистая архитектура с чётким разделением ответственности (Separation of Concerns):
   Логика строго разделена по слоям (api/, core/, clients/, tasks/, models/). Это делает код легко тестируемым и поддерживаемым. Слой базы данных (crud.py) ничего не знает о веб-фреймворке, а роутеры API занимаются только валидацией и маршрутизацией.
 * Инкапсуляция БД (Класс DatabaseManager):
   Отказ от глобальных переменных состояния (engine, sessionmaker) в пользу класса-менеджера. Это упрощает управление жизненным циклом сессии и централизует обработку rollback, делает Dependency Injection (DI) в FastAPI кристально чистым.
 * Плоская структура ответов API (Flat JSON):
   Вместо избыточных вложенных структур с динамическими ключами используется плоский массив [{"ticker": "btc_usd", "price": 81949.11, "timestamp": 1792126140}]. Это является стандартом REST, напрямую мапится в Pydantic-схемы без промежуточных преобразований и упрощает парсинг на стороне клиентов.
 * Асинхронность на всех уровнях:
   Использован асинхронный стек: от HTTP-запросов к бирже через aiohttp (с переиспользованием сессий) до работы с базой данных через драйвер asyncpg. Тяжелые синхронные фоновые задачи вынесены в Celery-воркеры.
 * Стратегия тестирования:
   Для интеграционных тестов API используется изолированная база данных в оперативной памяти (aiosqlite), что делает прогон тестов молниеносным. Запросы к внешнему API Deribit в тестах Celery-воркера полностью изолированы с помощью unittest.mock. Протестированы негативные сценарии (падение сети, частичный отказ, некорректный формат ответа от биржи).

 Запуск проекта (Docker)
 * Клонируйте репозиторий:
 
   git clone <ваш-репозиторий>
   cd <папка-проекта>

 * Настройте переменные окружения:
   В корне проекта скопируйте файл-пример и при необходимости измените данные:

   cp .env.example .env

 * Запустите контейнеры через Docker Compose:

   docker compose up -d --build

Приложение будет доступно по адресу: http://localhost:8000
Интерактивная документация (Swagger): http://localhost:8000/docs

API Endpoints
GET /api/prices?ticker=btc_usd - Получить всю историю цен по указанному тикеру.

Пример ответа:
[
  {"ticker": "btc_usd", "price": 80000.0, "timestamp": 1700000000},
  {"ticker": "btc_usd", "price": 81000.0, "timestamp": 1700000060}
]

GET /api/prices/latest?ticker=eth_usd - Получить самую последнюю актуальную цену по тикеру.

Пример ответа: {"ticker": "eth_usd", "price": 3000.5, "timestamp": 1700000060}

GET /api/prices/filter?ticker=btc_usd&timestamp=1700000000 - Получить цену на конкретный момент времени.

Пример ответа: {"ticker": "btc_usd", "price": 80000.0, "timestamp": 1700000000}

GET /health - Проверка жизнеспособности сервиса. Возвращает 200 OK с телом {"status": "ok"} при доступности приложения.

Пример ответа: {"status": "ok"}

🧪 Запуск тестов
Тесты можно запустить локально (требуется установленный pytest) или внутри контейнера.
Запуск тестов внутри Docker:

docker compose exec api pytest -v

CI/CD пайплайн настроен на автоматический прогон тестов при каждом push-событии в репозиторий.
